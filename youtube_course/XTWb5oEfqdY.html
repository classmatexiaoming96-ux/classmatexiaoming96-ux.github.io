一、问题引入：Claude 不是“聊天窗口”，而是一套分层工作系统

这支视频的价值不在于逐个按钮演示，而在于给 Claude 建了一张能力地图。很多人打开 Claude，只停留在输入问题、等待回答的阶段；但视频反复强调，Claude 的真实形态更像一个分层生态：底层是聊天、网页搜索、Artifacts、Memory、Styles、Projects；中间层是 Connectors、Skills、Extended Thinking、Research；再往上则是 Claude Code、Co-work、Computer Use 这类能触碰文件、工具和界面的 agentic 能力。

对学习者来说，这个分层很重要。你不需要一开始就冲向 Claude Code 或 Computer Use，也不应该把所有任务都塞给最高级能力。更稳妥的路径是：先把“什么时候需要实时搜索、什么时候需要结构化输出、哪些偏好应该进入 Memory、哪些上下文应该放入 Project”想清楚，再进入连接器、技能和代码代理。这样 Claude 才不是一个临时答题器，而会逐渐变成可复用的工作系统。

基础层Chat、Web Search、Artifacts、Memory、Styles、Projects，解决日常问答、文档、偏好和上下文管理。
增强层Connectors、Skills、Extended Thinking、Research，把 Claude 接入真实工作资料，并让重复流程标准化。
Agentic 层Claude Code、Co-work、Computer Use，让 Claude 开始处理文件、代码和可操作界面。

二、核心概念解释：先分清模型、上下文和工具

Haiku、Sonnet、Opus 不是“越贵越好”的线性选择

视频用跑步选手的比喻解释模型层级：Haiku 适合快速、轻量、低成本的短任务；Sonnet 是多数人的日常主力，兼顾速度和推理能力；Opus 则用于更慢但更难的分析，例如长文档、复杂判断、细致策略或需要多步推理的问题。这里的关键不是背模型名，而是形成任务分流：快问快答不必消耗高阶模型，真正要“想清楚”的任务才值得切到更强模型。

Memory 与 Projects 解决的是两种不同上下文

Memory 更像跨会话的个人偏好和长期事实，例如你的目标、写作风格、常用工作流；Projects 更像一个独立工作区，把同一主题的聊天、文件、指令和上下文集中管理。把两者混用会带来噪音：项目临时资料不应进入长期记忆，长期偏好也不该每次都靠文件重复上传。视频的隐含建议是，把 Memory 看成“个人层”，把 Project 看成“任务层”。

Artifacts 把一次回答变成可操作资产

Artifacts 是很多用户低估的功能。Claude 生成表格、页面、图表、二维码或结构化内容时，可以把结果放进独立面板，用户可以继续对话、修改和下载。它改变的是工作方式：不是“复制一段回答到别处”，而是在同一个对话里生成一个可以被迭代的半成品。对非开发者来说，这是从聊天走向轻量应用制作的第一步。

三、关键论点与实操路径：从个人助理走到工作代理

1. 先把实时性问题交给 Web Search

视频提醒，Claude 的训练数据有截止日期。如果问题涉及当前价格、最近新闻、上月变化、工具版本或政策更新，就应该打开 Web Search。反过来，如果你只是要改写、总结、构思、分析已有材料，关闭搜索反而能减少外部噪音。这个判断会直接影响答案质量：该联网时不联网会过时，不该联网时联网会分散注意力。

2. 用 Styles 管住输出口吻，而不是每次重复提示词

Styles 的作用是把输出方式固定下来，例如“简洁、正式、解释型、销售型、技术型”。如果你经常要求 Claude 用某种语气写邮件、提案、说明文或报告，就应该把风格沉淀下来。它和 Memory 的关系是：Memory 记住你是谁、你做什么；Styles 约束本次输出长什么样。

3. 用 Connectors 连接工作现场

Connectors 把 Claude 接到 Gmail、Google Drive、Docs、Slack、Notion、Calendar 等工具。视频强调它不是复制粘贴，而是让 Claude 从实际工作资料中读取、整理和写回。最适合连接的不是“看起来高级”的工具，而是你每天真正处理信息的地方。比如邮箱总结、Drive 文档检索、日历周计划，都是 Connectors 的典型入口。

4. 用 Skills 固化可重复流程

Skills 是视频中特别值得关注的一段：它把一套稳定步骤变成可复用能力。比如作者举例的 YouTube metadata skill，本质是把标题、描述、标签、发布格式这些重复任务做成标准流程。对于个人工作流，最好的 skill 候选通常不是一次性大任务，而是“每周都做、每次格式相似、但又容易忘细节”的任务。

5. Extended Thinking 和 Research 适合高不确定性任务

当任务不是简单生成，而是需要权衡、比较、拆解、多源整理时，Extended Thinking 和 Research 的价值才出来。前者让模型先推理再回答，适合复杂决策；后者更像把 Claude 派出去做资料收集和综合，适合竞品研究、市场扫描、资料汇总。它们都不该滥用，因为会消耗更多配额和时间。

6. Claude Code 与 Computer Use 是最后一级，不是入门捷径

视频最后进入 agentic 层：Claude Code 可以在项目文件中读写代码、运行命令、修 bug、加功能；Computer Use 则让 Claude 看屏幕、移动光标、点击和输入，适合结构化、步骤明确的界面任务。这里的风险也更高，因为它们从“回答问题”进入了“改变环境”。所以更合理的学习顺序是先学会描述结果、提供上下文和验证输出，再让 agent 接触文件或界面。

五、引用块：这节课真正想让你记住什么

Claude 的核心不是多一个聊天入口，而是从基础问答、结构化输出、长期记忆、连接器、技能，到代码和界面代理的一条能力阶梯。

这句话是对视频主线的转述。它提醒我们，学习 Claude 不应该只问“哪个功能最强”，而应该问“我现在的工作流在哪一层卡住”。如果卡在资料新鲜度，就补 Web Search；如果卡在重复格式，就补 Styles 或 Skills；如果卡在项目上下文，就补 Projects；如果卡在真实执行，才进入 Claude Code 或 Computer Use。
