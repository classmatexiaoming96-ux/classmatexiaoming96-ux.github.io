引入 Model Context Protocol

原文：Introducing the Model Context Protocol

导读

MCP 是 Anthropic 提出的开放协议，用来连接 AI assistant 与真实数据源、业务工具和开发环境。它把“给模型上下文”从一次性集成问题，变成可复用、可治理、可扩展的协议层。

说明：本文按 Agent Learning 的中文阅读页格式，对原文结构与关键技术细节做中文转述与解读。

核心观点

  • MCP 是连接 AI assistants 与数据源、工具、开发环境的开放标准。
  • 它试图替代碎片化 connector，让模型通过统一协议访问上下文。
  • 架构包括 MCP servers 和 MCP clients：前者暴露数据，后者连接并使用数据。
  • 发布时包含 protocol specification、SDKs、Claude Desktop 本地 server 支持和开源 server 仓库。
  • 预置服务器覆盖 Google Drive、Slack、GitHub、Git、Postgres、Puppeteer 等。
  • 开发工具公司可以用 MCP 帮 agent 获取代码任务周边上下文，减少尝试次数。
  • MCP 的长期价值在于跨工具、跨数据源维持上下文连续性。
  • 开放标准让安全和权限可以沉到基础设施层，而不是每个集成重新发明。

正文

为什么需要 MCP

模型能力快速提升，但 AI assistant 仍受困于数据孤岛和 legacy systems。每接入一个数据源都要自定义实现，导致真正 connected 的系统很难规模化。

MCP 的目标是提供一个通用开放标准，让 AI 系统以统一方式连接数据源。这样开发者不必为每个工具写一套专用 connector，模型也能拿到更相关的上下文。

协议架构

MCP 支持开发者构建安全的双向连接。数据源侧可以暴露 MCP servers；AI 应用侧作为 MCP clients 连接这些 servers。这个分工让数据提供、权限控制和模型使用之间形成清晰边界。

Anthropic 初始发布了三部分：MCP specification 和 SDKs、Claude Desktop 本地 MCP server 支持、以及开源 MCP servers 仓库。

开发者生态

文章提到 Claude 3.5 Sonnet 能快速构建 MCP server implementations，因此组织可以更快把重要数据集接入 AI tools。预置 servers 包括 Google Drive、Slack、GitHub、Git、Postgres 和 Puppeteer。

早期采用者包括 Block 和 Apollo；Zed、Replit、Codeium、Sourcegraph 等开发工具公司也在探索 MCP，让 coding agents 更好检索任务上下文，生成更准确的代码。

从碎片集成到可持续架构

没有协议时，每个数据源、工具和 agent 都要点对点集成，维护成本高，权限和安全也容易不一致。MCP 让开发者面向一个标准协议构建，随着生态成熟，AI 系统能在不同工具和数据集之间保持上下文。

这正是 agent 基础设施的关键：上下文不是 prompt 里的临时文本，而是可请求、可授权、可审计、可扩展的资源。

深度解读

MCP 的意义不只是“让 Claude 连上更多工具”。它更像 agent 时代的 USB-C：把不同数据源、工具能力和权限边界封装成统一接口。对企业来说，MCP 可以降低集成成本；对安全来说，它把权限、连接和审计放到协议层；对开发者工具来说，它让 coding agent 不再只靠打开文件猜上下文，而能以结构化方式获取仓库、issue、数据库和浏览器状态。

落地启示

  • 把内部系统接入 agent 前，先设计统一 connector 协议，不要堆临时 API glue。
  • MCP server 应遵守最小权限、可撤销授权和可审计日志。
  • 为 coding agent 提供 GitHub、数据库、浏览器和文档上下文，比单纯塞 prompt 更稳定。
  • 区分本地开发 MCP server 和远程生产 MCP server 的安全边界。
  • 把开放协议视为 agent 生态的长期基础设施，而不是单产品功能。
