让 Claude Code 更自主地工作

原文：Enabling Claude Code to work more autonomously

导读

Anthropic 发布 Claude Code 的 VS Code extension、2.0 terminal interface、checkpoints 和 Agent SDK 能力，让 Claude Code 更适合长任务、自主执行和可回滚探索。

说明：本文按 Agent Learning 的中文阅读页格式，对原文结构与关键技术细节做中文转述与解读。

核心观点

  • Claude Code 新增 native VS Code extension，提供 sidebar 和 inline diffs。
  • Terminal interface 更新了状态可见性和 searchable prompt history。
  • Claude Agent SDK 暴露 Claude Code 的 core tools、context management 和 permissions frameworks。
  • SDK 支持 subagents 和 hooks，便于构建自定义 agentic experiences。
  • checkpoints 会在 Claude 每次修改前保存代码状态。
  • 用户可通过 Esc 两次或 /rewind 回到旧状态。
  • subagents、hooks、background tasks 支撑并行和长任务。
  • Sonnet 4.5 成为 Claude Code 默认模型。

正文

Claude Code 进入更多工作界面

VS Code extension 把 Claude Code 从终端带到 IDE。用户可以在 sidebar 中实时看到 Claude 的修改和 inline diffs，这降低了不习惯终端用户的上手成本，也让 review 更直观。

终端侧则增加更好的状态可见性和 Ctrl+r prompt history，帮助用户复用和调整过去的任务描述。这个细节很工程化：长任务 agent 的可控性，很大一部分来自用户能不能快速恢复上下文和命令历史。

Checkpoints 给 autonomy 上安全绳

复杂开发任务需要探索、试错和迭代。checkpoints 在 Claude 每次修改前自动保存状态，用户可以 rewind 代码、对话或两者。它不替代 git，但降低了让 agent 做更大范围改动的心理成本。

这和 subagents、hooks、background tasks 形成组合：subagents 并行做专门任务，hooks 在特定点自动运行测试或 lint，background tasks 让 dev server 等长进程不阻塞主线。

Agent SDK 的产品意义

Claude Agent SDK 让团队可以基于 Claude Code 同一套工具、上下文管理和权限框架构建自己的 agent。文章提到金融合规、网络安全、代码 debug 等场景，说明 Claude Code 正从单一产品变成 agent runtime 的参考实现。

深度解读

这篇文章的关键词不是“更强”，而是“可放心委托”。agent 想做长任务，必须同时有可视界面、可回滚状态、可插入自动验证、可并行 subagents 和可持续后台任务。没有这些工程护栏，autonomy 只会让用户焦虑；有了这些机制，用户才敢把 refactor、feature exploration 这类宽任务交给 Claude Code。

落地启示

  • 长任务 agent 必须有 checkpoint 或等价回滚机制。
  • 把 tests、lint、format 放进 hooks，形成自动验收闭环。
  • subagents 适合并行探索，但需要主 agent 汇总和裁决。
  • IDE 和 terminal 两种入口应共享同一套上下文和权限模型。
  • background tasks 是本地开发 agent 的基础设施，不是附加功能。
